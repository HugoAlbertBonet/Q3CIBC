# libero_goal_pixels — IBC on the SAME visual backbone as q3c / dpq3c.
#
# Submit with:  bash submit_experiments.sh batches/lgIBCresnet.txt
# Prereq:       uv sync --extra libero    (resnet18 needs torchvision)
#
# ── What changed in the code to make this possible ─────────────────────────
# hyperparam_search_dfo.py hardcoded the pixel encoder to conv_maxpool at both
# the training build and the eval rebuild, so every libero IBC number to date
# (6 trials, 0.30-0.46) was produced on a weaker visual backbone than the
# algorithms it was being compared against. That was a structural handicap, not
# a property of IBC.
#
# Both sites now read the encoder from hparams / norm_stats:
#     ENCODER_KIND        conv_maxpool | resnet18
#     ENCODER_PRETRAINED  false | "imagenet"
#     ENCODER_NORM_KIND   bn | gn | bn_frozen
#     ENCODER_NUM_KP      SpatialSoftmax keypoints
#     ENCODER_PER_CAMERA, COND_FUSION (concat | film)
# Defaults reproduce the old behaviour exactly, and checkpoints written before
# this change have no encoder fields in norm_stats so they still rebuild as
# conv_maxpool. Existing trials stay reproducible.
#
# Verified: train-side kwargs and eval-side rebuild kwargs are identical, the
# "imagenet" string maps to the bool the model expects, eval forces
# pretrained=False (weights come from the state_dict, and compute nodes may have
# no network), and a legacy checkpoint with no encoder fields still resolves to
# conv_maxpool. The conv_maxpool state_dict round-trips train -> eval. The
# resnet18 path could not be exercised locally — no torchvision in this venv —
# so the FIRST job is the real test of it; watch for the backbone line
#     EBM backbone: PIXEL resnet18 (pretrained=..., kp=128, norm=gn) + ...
# in the log before trusting the rest of the batch.
#
# ── The remaining handicap, which this does NOT fix ────────────────────────
# There is still no ACTION_CHUNK in the dfo search space, so IBC runs unchunked
# while q3c's 82.0 and dpq3c's 78.8 both use action_chunk 16. Chunking is the
# largest single effect measured anywhere in this project. So even these runs
# are a lower bound on IBC, just a much tighter one. Adding chunking to the dfo
# trainer is a bigger change (the Langevin sampler, the action bounds and the
# eval sim all assume a single-step action) and is the next thing to do if the
# resnet numbers land close to q3c.
#
# ── Reference points on this env (3 seeds, 50 evals/seed unless noted) ─────
#     Q3CIBC ImageNet (chunk8)      86.7
#     Q3CIBC scratch  (chunk16)     82.0
#     dpq3c ALIGN scratch chunk16   78.8   (mean of 5 runs, sd 3.0)
#     Diffusion Policy (scratch)    68.3   (paper)
#     IBC conv_maxpool, unchunked   46.0   (best of 6, n=50) <- what this replaces
#
# ── The sweep (10 jobs) ────────────────────────────────────────────────────
#   RN_s0/1/2       resnet18 + GroupNorm + 128 keypoints + crop 116, 3 seeds
#   RN_imnet_s0/1   + ImageNet trunk (q3c gains +4.7 from this here)
#   RN_film_s0      cond_fusion film — the variant behind q3c's own best trial
#   RN_nocrop_s0    resnet18 without the crop, separating encoder from crop
#   RN_S4096_s0     resnet18 with a 4096-sample inference cloud
#   CONV_ctrl_s0/1  CONTROL: old conv_maxpool backbone, everything else identical
#
# The controls matter: without them a jump from 0.46 could be credited to the
# encoder when it was really the crop, the extra 50k steps, or the larger
# inference cloud, all of which also changed from the old trials.
#
# COST: IBC eval runs INFERENCE_NUM_SAMPLES x INFERENCE_NUM_ITERATIONS energy
# evaluations per action (2048 x 100 = 204,800; the S4096 line doubles that),
# and resnet18 is heavier per evaluation than conv_maxpool. Expect these to be
# the slowest jobs in the project. Drop RN_S4096 first if they hit the wall.
#
# Standard 50 eval episodes, inherited from the env config, never overridden.
