#
# Submit with:  bash submit_experiments.sh batches/ppDPQ3C4.txt
# Prereq:       uv sync --extra pushing
# Companion:    batches/ppREEVAL.txt — the eval-side half of this, which costs
#               minutes per job instead of ~29 h and should be run FIRST.
#
# ── Why these axes and not more of the last ones ───────────────────────────
# Round 2 closed out most of the training-side grid:
#   actor length 100k -> 400k        +0.25   z=+4.30  p<0.0001   the one big lever
#   margin, at a good actor          +0.01..+0.07      noise/marginal
#   progress_weight                  neutral in THREE separate measurements
#   dp_negatives 128 vs 64           +0.02   p=0.62
#   dp_negatives 64 vs 0 (alone)     +0.04   p=0.41
#   seed floor on this env           0.03
# Re-running those with new values would mostly re-measure noise. What has never
# been varied at all is the ACTOR's own capacity and diffusion process, and how
# its training negatives are drawn. Six of the eight lines below are axes with
# zero prior measurements.
#
#   CAP_w2048 / CAP_d2   The denoiser head has been 1024x1 in every run, copied
#                        from the plain-DP recipe. But in dpq3c the actor also
#                        has to supply the critic's negatives, so it is doing
#                        strictly more work than a standalone DP for the same
#                        capacity. Untested.
#   T50 / T200           num_train_timesteps has been 100 throughout. The chain
#                        length trades sample fidelity against how far each
#                        denoising step has to move, and it interacts with the
#                        eval step count that ppREEVAL sweeps.
#   NEG_DDPM             Training negatives have always been drawn with the
#                        deterministic DDIM chain. Ancestral DDPM gives a more
#                        diverse cloud at the same count — plausibly harder and
#                        better-spread negatives, which is the whole point of
#                        drawing them from the actor.
#   QACTOR_retest       q_actor_weight was noise at 100k (p=0.44), but so was
#                        the margin, and the margin's story changed completely
#                        once the actor worked. Pulling the denoiser's predicted
#                        clean sample toward high Q deserves one look on an actor
#                        that can actually denoise.
#
# The two 550k arms are kept because actor length is the only demonstrated large
# effect and 550k has never been run. They are a PAIR on purpose: one with the
# critic terms on and one off, so a gain can be attributed to the extra steps
# rather than to the terms. ~40 h each at the measured 0.073 h/1k, inside the
# 48 h wall with ~7 h of margin. Do NOT raise this to 750k in one job — that is
# ~55 h and would be killed at the wall with nothing recorded. If 550k still
# improves, the right move is checkpoint-resume support in dpq3c_training.py so
# a full 750k run splits across two jobs.
#
# Everything not named above is pinned to the round-2 best cell (trial 21, 0.95):
# 400k steps, v-prediction, dp_negatives 64, margin 0.5 at m 0.5, progress 0.1.
