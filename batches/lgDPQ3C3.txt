# entire story: 0.22 -> 0.76-0.88 across EVERY cell, control included.
#     round-2 control 0.76  vs  round-1 best 0.22    z=+6.42  p<1e-6
# and the best cell now sits within noise of the q3c baseline:
#     round-2 best 0.88     vs  q3c trial 76 0.96    z=-1.49  p=0.14
#
# But the seed replicate killed every algorithmic conclusion. Same config, two
# training seeds:
#     B seed0 = 0.88     F seed1 = 0.60     delta = 0.28   z=+3.37  p=0.0008
# That gap exceeds what eval sampling alone can produce at n=50 (SE_diff 0.083),
# so it is genuine RUN-TO-RUN TRAINING variance. And it is larger than every
# other difference in the round-2 table:
#     margin+prog vs no-terms  +0.10  | margin only  +0.08  | progress only  0.00
#     control vs DP-negatives  -0.02  | imagenet     +0.10  | n=128         -0.10
# All six are inside the seed spread. Round 2 resolved nothing about the
# algorithm — one seed per cell cannot, at this variance.
#
# So round 3 changes ONE thing: it spends the budget on replication instead of
# on new axes: three configs, four training seeds each, at the env's STANDARD
# 50 evaluation episodes. Matching the protocol every other algorithm on this
# env was scored with keeps these numbers directly comparable to the q3c and
# IBC records already in trials.jsonl. Averaging over four training seeds is
# what tightens the estimate here, not a bigger per-trial episode count.
#
# ── The ladder (3 configs x 4 seeds = 12 jobs) ─────────────────────────────
#   CTRL   dp_negatives 0        — critic never sees a diffusion sample
#                                  (uniform + Langevin negatives), i.e. a
#                                  Q3C-style critic bolted onto a DP actor
#   ALIGN  dp_negatives 64       — negatives drawn from the actor itself
#   FULL   ALIGN + margin 0.5@0.1 + progress 0.1
#
# Read it as MEANS OVER FOUR SEEDS with their spread, never as single numbers.
# The question is only: does ALIGN beat CTRL, and does FULL beat ALIGN, by more
# than the seed spread? If the three rungs overlap after four seeds each, the
# critic is not contributing on this task and the next move is the architecture
# (a noise-conditional critic), not another hyperparameter grid.
#
# A second thing worth extracting: the SPREAD itself, per rung. A policy whose
# success swings 0.60-0.88 with the training seed is not something to deploy on
# a robot regardless of its mean. If one rung is visibly tighter than the
# others, that is a result in its own right and arguably a more useful one.
#
# ── CORRECTION to the round-2 note ─────────────────────────────────────────
# batches/lgDPQ3C2.txt warned that final_train_accuracy above ~0.9 means the
# actor is broken. That was wrong for this env. Round 2 shows train accuracy
# pinned at exactly 1.000 in every cell WHILE success rose 0.22 -> 0.88. With
# action_chunk 16 on a 7-DoF arm the action is 112-dimensional, and telling the
# true expert chunk from any sampled chunk is trivial in 112 dimensions no
# matter how good the actor is. The diagnostic holds on pushing_pixels (2-D
# actions, train accuracy 0.29-0.41) but carries no signal here — ignore it on
# libero rather than reading it as a failure.
#
# ── Timing ─────────────────────────────────────────────────────────────────
# Round-2 jobs ran 14-21 h at 200k steps with 50 eval episodes; round-1 jobs of
# the same size ranged 12-28 h purely on node draw. Eval is a small share of
# that, so 200 episodes should land inside the 48 h wall with margin. If jobs
# start hitting the wall, drop a seed before cutting steps — training length is
# what bought the round-2 jump.
