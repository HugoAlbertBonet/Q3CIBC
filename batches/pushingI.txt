# Batch pushingI — ablation control: is the win from the LEARNED proposal?
#
# Every result so far shows Q3C matching or beating IBC while scoring ~20
# candidates instead of 16,384. Two explanations are consistent with that:
#
#   (a) the control-point generator proposes good actions  (our claim), or
#   (b) the task simply does not need many candidates, and 20 uniform draws
#       would do just as well.
#
# Nothing in the existing results separates them. `inference_dfo_num_uniform`
# only ADDS uniform samples to the control points; it never replaces them.
#
# This batch runs the missing control. `inference_uniform_proposal: true`
# discards the generator at EVALUATION ONLY and draws the same number of
# candidates (20) uniformly from the action box. Training is byte-identical to
# pushingH, so these rows pair directly with pushingH trials 66-71:
#
#   pushingH 66-68  learned proposal, CP-argmax     99.0 +/- 1.0
#   pushingH 69-71  learned proposal, CP-DFO 3 it   100  +/- 0
#   pushingI below  uniform proposal, same two recipes, same three seeds
#
# Reading the outcome:
#   uniform collapses  -> the generator is the contribution. Report as the
#                         paper's key ablation.
#   uniform matches    -> the method reduces to "IBC with far fewer samples",
#                         which is still a result, but a different paper.
#
# Six jobs, 200k steps each, matching pushingH exactly except for the eval flag.
# Training is unaffected by the flag, so if an eval-only path is added later
# these can be replaced by re-evaluating the pushingH checkpoints.
#
# Run:  ./submit_experiments.sh batches/pushingI.txt pushingI
