# Batch pushingMultiTier2 — Tier 2 multimodality benchmark (see conversation
# "design a test that can visually show Q3C's capability to adapt to
# multimodality"). Companion to Tier 1 (batches/dummyBimodalTier1.txt): where
# Tier 1 is a controllable toy for qualitative CP-cloud/Q-heatmap figures,
# Tier 2 is IBC's OWN literature-established multimodal benchmark
# (BlockPushMultimodal — 2 blocks, 2 targets, Florence et al. 2021 Table 3),
# used for a quantitative "mode coverage" number that also appears in the
# Diffusion Policy paper's multimodality comparison.
#
# Four methods, 2 seeds each:
#   pmT2_q3c*  : Q3C (combinedv2_cpascounter_training.py). Hyperparams mirror
#                pushingMultiA4 (batches/pushingMultiA.txt) — the first
#                IBC-paper-faithful recipe PLUS training-time Langevin
#                negatives, the config most likely to actually solve this env
#                (see that file's header for why multiA1-3 were predicted to
#                sit near 0%).
#   pmT2_ibc*  : Paper-faithful Implicit BC (ibc_with_cpsv2_training.py) —
#                Langevin-MCMC-negatives-only, no generator-side CP mixture.
#                num_hidden_layers/num_neurons chosen to match Q3C's
#                estimator capacity (128-wide x 8 layers ~= q_width=128
#                q_depth=8 resnet); counter_examples=8 matches IBC paper's
#                ImplicitBCAgent.num_counter_examples for this task.
#   pmT2_bc*   : Explicit BC-MSE (bc_mse_training.py) — mode-collapse
#                control, SAME cp_width/cp_depth (256x2 MLP) as Q3C's
#                generator as its regression head, so any success-rate gap
#                is attributable to the objective, not capacity — same
#                rationale as batches/pushtWidowXbc.txt.
#   pmT2_dp*   : Diffusion Policy (diffusion_policy_training.py, run through
#                hyperparam_search_dp.py so DDPM + every DDIM step count are
#                evaluated from one checkpoint) — second mode-preserving
#                reference; recipe mirrors batches/pushingDPA.txt (the
#                single-target DP arm) unchanged except active_env.
#
# Prereqs (one-time, off-cluster, before submitting):
#   - Download + unzip the IBC multimodal oracle TFRecords:
#       https://storage.googleapis.com/brain-reach-public/ibc_data/block_push_multimodal_states_location.zip
#     -> datasets/block_push/block_push_multimodal_states_location/
#   - uv sync --extra pushing   (PyBullet + gym; NOT on the base .venv)
#
# After all arms finish, run the Tier 2 mode-coverage analysis (add
# --checkpoint-dir/--label pairs for however many methods you want compared):
#   uv run --extra pushing python -m simulations.run_pushing_multi_multimodality_eval \
#     --checkpoint-dir checkpoints/hpsearch/<q3c_trial_dir> --label Q3C \
#     --checkpoint-dir checkpoints/hpsearch/<ibc_trial_dir> --label IBC \
#     --checkpoint-dir checkpoints/hpsearch/<bc_trial_dir>  --label BC-MSE \
#     --output-dir results/pushing_multi
# (DP isn't wired into that eval script yet — it needs the DDPM/DDIM sampler
# from hyperparam_search_dp.evaluate_dp instead of evaluate_q3c; extend
# evaluate_checkpoint() there the same way if you want DP on the same plot.)
# -> results/pushing_multi/mode_coverage.png + mode_coverage.csv:
#    success rate on genuinely-ambiguous start configs (both block->target
#    assignments similarly short) vs unambiguous ones, per method. Expect
#    BC-MSE's gap (unambiguous - ambiguous success rate) to be much larger
#    than Q3C's/IBC's/DP's if mode-collapse is actually costing it task
#    success, not just "wrong-looking but still fine" trajectories.
