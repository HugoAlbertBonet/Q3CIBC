# Wire-fitting Q3C — interpolate the expert, the negatives, or both;
# Langevin negatives from the raw network or from the interpolant.
#
# Submit with:  bash submit_experiments.sh batches/wfModes.txt
# Prereq:       uv sync --extra libero --extra pushing   (pen and kitchen use neither)
#
# ── Why every mode is here, not only "the most successful combination" ─────
# No interpolating mode has ever been run, so the most successful one is what
# this batch finds out. From each environment's best combinedv2 reference
# config: none and interp_negatives at two seeds (0, 1); interp_both at seed 0
# only, since one run is enough to confirm or refute its predicted structural
# failure:
#
#   interp_negatives  estimator scores the control points and the EXPERT
#                     directly; counter-examples interpolated from the wires.
#                     Predicted to hold combinedv2 performance: the objective is
#                     satisfiable, and it amounts to combinedv2 with the
#                     negatives smoothed through the control-point interpolant.
#   interp_expert     NOT RUN (cut to save jobs). Estimator scores the control
#                     points and counter-examples directly; expert interpolated.
#                     Fails by the same mechanism as interp_both, which stands in
#                     for it: on 512 random states the expert out-scored every
#                     negative in exactly 0.000 of them, and a 40-step smoke run
#                     trained at Acc 0.000.
#   interp_both       estimator scores ONLY the control points; expert and
#                     counter-examples both interpolated from the wires.
#                     Predicted to degrade. The interpolated expert can never
#                     exceed the best wire; the top-k counter-examples always
#                     contain that wire (top-k is selected BY Q), and interpolated
#                     AT a wire its value is exactly max_i q_i. The expert can
#                     only tie it.
#                     Free-score test: loss 1.86, expert wins 0.000.
#
#   interp_both becomes satisfiable only with
#   infonce_positive_cp_radius > 0: control points near the expert then count as
#   positives (free-score test at radius 0.5: loss 0.0022, wins 1.000).
#   No reference sets it and its default is 0. A useful value depends on how
#   close trained control points get to the expert, so it is NOT set here and
#   the arm runs as the reference specifies.
#
#   none              byte-for-byte combinedv2, same script, same seeds: the
#                     control. The reference trials below are best-of-N single
#                     runs (pushing_pixels' 0.99 averages 0.900 over 3 seeds in
#                     the ablation), so they are NOT the comparison — this is.
#
# ── Langevin negatives: raw chain vs interpolant chain ─────────────────────
# Crossed with every mode run: wirefit_langevin_on_interpolant false | true.
#   false  the chain ascends the raw network (combinedv2's IBC negatives).
#   true   the chain ascends the wire-fitted Q, built from the control points and
#          the scores already computed to pick the top-k negatives. No network
#          call inside the loop.
# The interpolant never exceeds the best control point, so the true chain cannot
# find an off-cloud action the raw network over-scores. Predictions:
#   libero        argmax deployment never reads off-cloud scores, so the
#                 interpolant chain should cost little. Most coherent cell:
#                 interp_negatives + true, where every counter-example is both
#                 found and scored on the wire-fitted Q.
#   pen, kitchen  deploy by Langevin refinement ON THE RAW NETWORK, whose
#                 off-cloud shape is what raw-chain negatives train. true is
#                 expected to cost performance here.
# pushing_pixels' reference uses no Langevin negatives (num_langevin_negatives 0),
# so the flag would be a no-op there: it runs the false arm only.
#
# ── What the reference configs carry, verbatim ─────────────────────────────
# Every parameter of each reference trial is copied as-is — 0 of them fall
# outside SEARCH_SPACE, so none is silently dropped. That matters most for:
#   pen      deploys with Langevin refinement, 25 iterations (lr 0.01 -> 1e-6)
#   kitchen  deploys with Langevin 50 + 30 "again" iterations
# config.json defaults both to 100 Langevin iterations, so omitting these keys
# would have evaluated a different policy than the reference — which is what
# happened to the kitchen line of the superseded wfKitchen.txt.
# pushing_pixels and libero deploy with plain argmax over the control points,
# the setting where wire-fitting's exact-argmax property actually applies.
#
# Gradient penalty stays at weight 1.0 / margin 1.0 as in every reference.
# config.json sets that in training_shared AND every env block, so these runs
# match how the references were trained even though GP overrides were routed
# wrongly before 2026-09-10. Note GP margin 1 is known to cripple argmax ranking
# (memory: q3c-particle16-argmax-blockers); it is kept here so only wirefit_mode
# and the Langevin chain vary within an environment.
#
# The generator's sign-swapped InfoNCE and the gradient penalty both stay on
# DIRECT evaluation in every mode — see the wirefit_q3c_training.py docstring.
#
# Wire-fitting knobs fixed at c = 0.1 and k = 10 (clamped to the cloud size:
# 20 / 100 / 200 / 100 control points respectively).
#
# pushing_pixels: (none, interp_negatives) x 2 seeds + interp_both x 1   =  5 jobs
# libero, kitchen, pen, each: ((none, interp_negatives) x 2 seeds
#                              + interp_both x 1) x 2 chains = 10       = 30 jobs
# total                                                                  = 35 jobs
