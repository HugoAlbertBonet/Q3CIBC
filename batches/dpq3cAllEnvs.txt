#
# Submit with:  bash submit_experiments.sh batches/dpq3cAllEnvs.txt
# Prereq:       uv sync --extra libero --extra pushing   (this file uses both)
#
# Covers: particle, pushing, pushing_multi, pen, door, kitchen, libero_goal.
# (pushing_pixels and libero_goal_pixels already have 75 and 101 records.)
#
# ── Expect the first job per environment to be a plumbing test ─────────────
# dpq3c's FLAT-state path — build_denoiser + QEstimator, and the flat branch of
# _build_dpq3c_generator in evaluate_q3c — exists and is wired, but has only
# ever been exercised on the synthetic `dummy` env. pen, door and kitchen each
# have their own simulation class and their own action conventions. Watch the
# first job of each environment reach `Step 1000/...` before assuming the rest
# of that environment's lines are sound; everything before that line is startup.
#
# ── The cloud=1 control, which is now the important measurement ────────────
# Re-scoring 18 checkpoints across both pixel environments showed that RANKING
# THE CLOUD DOES NOT HELP: paired, same checkpoint, ranking on vs removed came
# out at 0.819 vs 0.834, hurting on 12 of 18, and significantly so on the
# strongest group (libero ImageNet, -0.027, p=0.046). The best single number in
# the whole project is dpq3c with the critic switched OFF (libero ImageNet at
# cloud 1: 91.3, against q3c's published 86.7).
#
# So for each environment here the control is not optional — it is the result
# most likely to matter. It is an EVAL-ONLY re-score, so it is not a line in
# this file. After training completes, generate its batch from trials.jsonl
# (that file is in the repo, so this runs on the laptop):
#
#   uv run python scripts/make_cloud1_batch.py --active-env pen \
#       --extra "" --out batches/penCLOUD1.txt
#
# then submit batches/penCLOUD1.txt where the checkpoints are. The generator
# skips any trial that already has a cloud=1 record, so it is safe to re-run.
#
# A cloud of 1 leaves the critic with nothing to rank, so that number is the
# policy's diffusion actor alone. If it matches or beats the cloud=64 number —
# as it has in both pixel environments — then dpq3c on that environment is a
# diffusion policy and should be reported as one.
#
# Optional terms are OFF everywhere (margin, progress, q_actor). On libero they
# were inert and tripled the run-to-run spread; on pushing_pixels they helped
# (+0.057, p=0.011), so that environment keeps them in its own batches, but
# there is no reason to carry an env-specific, unexplained effect into seven new
# environments on the first pass.
#
# 2 seeds per environment. Batch sizes follow each env's existing convention.
