# Batch dummyBimodalTier1 — Tier 1 multimodality visual demo (see
# conversation "design a test that can visually show Q3C's capability to
# adapt to multimodality").
#
# Env: dummy_bimodal (simulations/dummy_bimodal_env.py) — 2D nav toy with a
# fixed circular obstacle at the origin. Whenever the direct agent->goal line
# crosses the obstacle, TWO equally valid detours exist (clockwise vs
# counterclockwise); the synthetic oracle (utils.datasets.DummyBimodalDataset)
# flips a coin ONCE per episode to pick a side, so the dataset is genuinely
# bimodal near the obstacle and unimodal everywhere else — the toy analog of
# IBC's own energy-landscape multimodality figure.
#
# Four methods, 2 seeds each, on the SAME dataset/env:
#   dbT1_q3c*   : Q3C (combinedv2_cpascounter_training.py) — control-point
#                 cloud + wire-fit Q should split into two clusters near the
#                 obstacle. Diagnostic plots (CP cloud, Q heatmap, twin-expert
#                 stars) via `python -m simulations.run_simulation` after
#                 training (set active_env=dummy_bimodal in config.json).
#   dbT1_ibc*   : Paper-faithful Implicit BC (ibc_with_cpsv2_training.py) —
#                 Langevin-MCMC-negatives-only variant, no generator-side CP
#                 mixture. The literature baseline Q3C is actually compared
#                 against; should also preserve both modes (energy-based).
#   dbT1_bc*    : Explicit BC-MSE (bc_mse_training.py) — the mode-collapse
#                 control. Expect it to regress toward the AVERAGE of the two
#                 valid headings near the obstacle, i.e. aim roughly straight
#                 at the obstacle and stall (hard-collision env punishes this
#                 visibly in success rate).
#   dbT1_dp*    : Diffusion Policy (diffusion_policy_training.py, run through
#                 hyperparam_search_dp.py so DDPM + every DDIM step count are
#                 evaluated from the one checkpoint) — second mode-preserving
#                 reference (stochastic sampler should also cover both
#                 detours).
#
# Prereqs: none beyond the base .venv — dummy_bimodal's dataset is synthetic
# (generated on the fly, no download). No --extra needed.
#
# After training, generate the visual diagnostic (5-panel snapshot plots,
# CP cloud + Q heatmap + twin-expert stars — works for q3c AND ibc
# checkpoints, both write control_point_generator.pt + q_estimator.pt) with:
#   1. Set "active_env": "dummy_bimodal" in config_json/config.json (or point
#      Q3C_CONFIG_PATH at a copy).
#   2. python -m simulations.run_simulation --checkpoint <ckpt_dir>/control_point_generator.pt \
#        --seeds 0 1 2 --episodes 6 --device cpu
#      -> plots/dummy_bimodal/ep*_step*.png
