# particle — Diffusion Policy across dimensionalities, DDPM and DDIM.
#
# Submit with:  bash submit_experiments.sh batches/dpParticle.txt
#
# ── One training per cell, both samplers evaluated ─────────────────────────
# DDPM and DDIM are two inference schedules over the SAME trained denoiser, not
# two models. So each line trains once and is scored under both: eval_ddpm true
# gives the full ancestral chain, and ddim_eval_steps [5,10,25] gives three
# sub-sampled deterministic chains. Four numbers per run, one training cost.
#
# ── Why v-prediction ───────────────────────────────────────────────────────
# On pushing_pixels the best DP recipe used prediction_type "v" and our first
# dpq3c round used "epsilon"; switching (together with a longer schedule) was
# worth +0.25 success, the largest single effect measured anywhere in this
# project. It costs nothing to carry over, so every line here uses it.
#
# ── Dimensionality ─────────────────────────────────────────────────────────
# 2, 4, 6, 8, 16, 32 — n_dim, action_dim and state_dim move together
# (state_dim = 2 * n_dim * frame_stack). Only 16D has ever produced scored q3c
# trials; 6D, 8D and 32D have empty results directories, and 2D/4D have never
# been touched. If the dataset does not carry a given n_dim the job fails fast
# during loading, so an unavailable dimension costs minutes, not a GPU day —
# cheaper to find out this way than to pre-verify each one.
#
# 2 seeds per dimension, because single runs are what misled us repeatedly.
